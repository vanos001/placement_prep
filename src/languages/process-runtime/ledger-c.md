Chapter: [./c.md](./c.md) — Section G, process runtime. This ledger inventories every documented
API and behavior claim in the chapter as one row each, ordered by chapter section (§1 syntax/
semantics behavior rows first, then §2–§6 API/behavior rows in order of first appearance).

**Scope.** ISO C17 (draft **N2310**) baseline with C23 deltas verified against draft **N3220**
(open-std.org; C99 deltas vs N1256); **POSIX.1-2024** / Issue 8 (pubs.opengroup.org); Linux
**man-pages 6.19** (man7.org); **glibc 2.44**, current stable verified via sourceware.org/glibc.
The GNU C Library manual (gnu.org) was unreachable from the retrieval environment, so every
glibc-behavior row cites the man page that documents glibc behavior instead (rows naming glibc
scope). Linux kernel UAPI: git.kernel.org was bot-protected and raw.githubusercontent
rate-limited at retrieval time, so kernel-side wait-status claims are anchored in man-pages 6.19;
the affected row (PL-C-067, `include/uapi/linux/wait.h`) is the ledger's single `source-limited`
entry.

**Status definitions.**

- `documented` — the claim is documented in `./c.md` and anchored to a fetched authoritative
  source (ISO draft clause, POSIX page, or man page) exactly as the chapter cites it. No further
  work remaining.
- `source-limited` — the claim is documented in `./c.md`, but the intended primary source (the
  raw Linux UAPI header) was unreachable at retrieval time; anchored to the closest fetched
  authority (man-pages 6.19) instead.
